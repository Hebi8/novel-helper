# Novel Helper 小说助手

[English](README.md)

在 VS Code 里写小说用的灰字续写，会参考你的设定。在章节里写到行尾停一下，灰字就会接着往下写一小段（默认最多 100 字，可以分段），按 **Tab** 收下。每次请求都会带上这一段需要的东西：本章已经写的正文、正文里出现的名字对应的设定条目、标了常驻的条目（文风要求、世界观总则）、全书到卷到本章的各层大纲，以及前面几章的摘要或结尾。花了多少 token、多少钱，随时能看。

看设定也只要一步：鼠标停在名字上出设定卡，按 **F12** 打开设定文件。

首先照顾中文长篇（一章一个文件、几百章、词之间没有空格），其他语言也能用。key 用你自己的：Anthropic、OpenAI、DeepSeek、Gemini，或者任何 OpenAI 兼容的端点，包括本地模型。

## 安装

1. 打出 `novel-helper-0.4.0.vsix`（见[从源码构建](#从源码构建)）。
2. VS Code 扩展视图 → `⋯` → **从 VSIX 安装…**，或者运行 `code --install-extension novel-helper-0.4.0.vsix`。用 Remote-SSH 时在远程窗口里装，扩展会跑在文件所在的机器上。

## 设置 API key

1. 命令面板 → **Novel Helper: 设置或清除 API key** → 选服务商 → 粘贴 key。
2. 用的不是 Anthropic 的话，把 `novelHelper.provider` 改成对应的服务商。

这两步也可以在[边栏](#边栏)的「设置和用量」里点着做。

key 存在 VS Code 的密钥存储（系统钥匙串）里，不会写进设置。要删掉，再运行一次这个命令，输入框留空直接回车。

| 服务商 | `novelHelper.provider` | 默认模型 | 思考 |
|---|---|---|---|
| Anthropic | `anthropic` | `claude-haiku-5-5` | 关掉：`"thinking": {"type": "disabled"}` |
| OpenAI | `openai` | `gpt-6-luna` | 关掉：`"reasoning_effort": "none"` |
| DeepSeek | `deepseek` | `deepseek-flash` | 关掉：`"thinking": {"type": "disabled"}` |
| Gemini（OpenAI 兼容端点） | `gemini` | `gemini-3.5-flash-lite` | Gemini 3 关不掉；这个模型默认是最低的 `minimal` 档 |
| 本地模型或其他 OpenAI 兼容端点 | `openaiCompatible` | 填 `novelHelper.openaiCompatible.model` | 看服务端 |

服务商、模型、地址、`extraRequestBody`、单价和日上限写在工作区设置里时，要信任这个文件夹才生效；受限模式下只认你的用户设置，没信任的文件夹没法把你的正文和 key 转发到别处，也没法取消你设的花费上限。

换模型改 `novelHelper.<服务商>.model`。模型需要别的请求字段时，写进 `novelHelper.extraRequestBody`：它会合并进每次请求，值写 `null` 会去掉那个字段。比如 Claude Sonnet 5.5 不接受 `disabled`，要这样关思考：

```json
"novelHelper.anthropic.model": "claude-sonnet-5-5",
"novelHelper.extraRequestBody": { "thinking": { "type": "between_tools" } }
```

用 Ollama：`novelHelper.provider` 设成 `openaiCompatible`，`novelHelper.openaiCompatible.model` 填模型名；默认地址 `http://localhost:11434/v1` 就是 Ollama 的，不用 key。

OpenAI 这一项按 GPT-5.6 及之后的模型发缓存断点（见[花多少钱](#花多少钱)）。更早的 OpenAI 模型不认这些字段，请用 `openaiCompatible`，地址填 `https://api.openai.com/v1`。

## 边栏

活动栏上多了一个「小说助手」图标，里面五个视图：下面四个，加上[助手](#助手)。边栏只管搭架子、改固定的字段；内容一律点开对应的 Markdown 文件写。

**书的结构**：全书 → 卷 → 大章 → 章，一棵树，就是正文目录的样子（不分卷时，全书下面直接是章）。

- 点章打开文件；正在编辑的章会在树里选中。
- 每个节点后面标着有没有大纲、摘要：`大纲 ✓ · 摘要 ✗`。行内的按钮打开它的大纲（章还有摘要），没有就先在该放的位置建一个空文件再打开。最上面的「全书」节点开的是全书大纲。
- **新建章**：名字按前面的章接着编号，`第11章 雾里来信` 后面预填 `第12章 `，`第十一章` 后面是 `第十二章`，补上标题回车就行。**新建卷 / 大章**：填卷名，再填它第一章的名字（卷是装着章的文件夹，有了章才会出现在树里）。
- 右键 **重命名** 卷、大章或章：它的大纲、摘要，以及大纲和摘要目录里对应的整层文件夹一起改名，一步完成，可以撤销。要带走的文件夹或文件如果还有别处在用（比如两卷里同名的大章共用一个大纲文件夹），就整个不改，一个文件都不动，并说明是哪一处被谁共用；先把它们分开，或者手动改名。
- 不做删除和拖动排序；删文件、挪文件用资源管理器，树会跟着更新。

**大纲**：大纲目录里的文件夹、文件和标题列成一棵树，标着节点之间的连线和当前章节写到了哪个节点，浮标在这里挪。见[大纲图和浮标](#大纲图和浮标)。

**设定**：按类型分组（frontmatter 的 `type`；没写就按所在的顶层文件夹）。

- 点条目打开文件。条目后面写着是不是常驻、有哪些别名。
- 行内按钮切换常驻、改别名；右键还能改类型。这些只改 frontmatter 里那一个字段，文件其余部分（别的字段、顺序、注释、正文）一个字不动；本来没有 frontmatter 的文件会加上。按 frontmatter 现在的写法做不到只改这一处时（比如整段写成 `{…}` 又缺这个字段，或者要换掉的值里夹着注释），不动文件并提示，请直接在文件里改。
- **新建设定条目**：选类型（或者输入一个新的）→ 填名字 → 按模板建好文件并打开。模板只有 frontmatter 骨架和两三个小标题。想用自己的模板，在工作区里放 `.novel-helper/templates/<类型>.md`（比如 `人物.md`），别的类型用 `default.md`；里面的 `{{name}}`、`{{type}}` 会换成条目名和类型（frontmatter 里按 YAML 的写法填，名字带冒号、括号也行）。

**设置和用量**：一行一项，点一下就改：[故事目录](#故事目录)、续写开关、自动还是手动触发、服务商、模型、API key（只显示已设置或未设置，从不显示 key 本身）、今天和本月的请求数与估算花费（点开是明细）、日上限、上次发给模型的内容。

**新开一本书**：打开一个空文件夹，边栏里会有「在这里初始化」按钮（命令面板里是「初始化小说工作区」）。它先问放在哪个目录、目录用中文名还是英文名（见[故事目录](#故事目录)），然后列出要建的东西让你勾选：正文、大纲、摘要、设定、人物、资料几个文件夹，一份只有几个提示词的全书大纲，一条常驻的「文风」条目，以及可选的第一卷（`正文/第一卷/第1章.md` 和 `大纲/第一卷.md`）。已经有的不会列出来，也不会被覆盖。

## 故事目录

故事不一定放在工作区的根上。`novelHelper.files.storyFolder` 是「故事目录」：相对于工作区文件夹的路径，留空就是工作区文件夹本身。正文、大纲、摘要、设定这些文件夹，还有 `.novel-helper/templates/`，都在故事目录里找；续写、设定卡、边栏、新建和重命名都以它为根，它外面的文件不算章节。不用手改设置：点边栏「设置和用量」最上面的「故事目录」一行，可以切到找到的故事空间、用文件夹选择框选、输入相对路径，或者回到工作区根。

- 一个工作区文件夹同一时间只有一个故事目录在用，多本书靠切换；多根工作区里每个文件夹各设各的。
- 路径只能在工作区文件夹里面。绝对路径、带 `..` 的值不会被采用，边栏会提示，不会去读工作区外面的东西。`novelHelper.files` 下的目录和全书名设置如果带 `..`、会让文件落到故事目录外面，初始化、新建和重命名都不执行，并说明是哪条路径。这些检查都按路径的字面来，不解析符号链接。
- 初始化时会先问放在哪个目录（不存在就新建）、目录用中文名还是英文名（默认跟 VS Code 的显示语言；`正文、大纲、摘要、设定、人物、资料` 或 `chapters、outlines、summaries、lore、characters、worldbuilding`，两种默认设置都认），建完把故事目录指过去。

初始化会在故事目录里留一个标记文件 `.novel-helper/project.json`，只记格式版本和建立时用的名字：

```json
{
  "version": 1,
  "language": "zh",
  "folders": { "chapters": "正文", "outlines": "大纲", "summaries": "摘要", "lore": ["设定", "人物", "资料"] },
  "book": "全书"
}
```

扩展靠它认出「初始化过的故事空间」。边栏按故事目录的状态显示：

- **能用**：有标记文件；或者没有标记、但里面已经有章节、大纲或设定（以前的版本初始化的，或者自己摆的）。照常显示树。后一种在「故事目录」一行写的是「在用」，不会有任何提示，想补标记的话，点「故事目录」一行里的「给这个目录补上标记」。
- **还没初始化**：目录不存在，或者里面什么都没有。显示说明和「在这里初始化」按钮。
- **用不了，但工作区里有别的故事空间**：按标记文件找（最多往下四层，跳过 `node_modules`、`.git` 和其他隐藏目录），把找到的列在「书的结构」里，点一下就把故事目录切过去。

本仓库的 [`examples/`](examples) 就可以这样用：把仓库根当工作区打开，故事目录设成 `examples`。

## 工作区怎么摆

打开放小说的文件夹（或者把[故事目录](#故事目录)指到它）。默认的摆法如下，都能在设置里改：

```text
我的小说/
├── 设定/        设定条目，一条一个文件（也认：人物/ 角色/ 资料/ 世界观/ lore/ characters/ worldbuilding/）
│   ├── 文风.md
│   └── 雾港.md
├── 人物/
│   └── 林小满.md
├── 正文/        章节，一章一个文件（也认：章节/ chapters/ manuscript/）
│   └── 第一卷 雾港/                 卷：一层文件夹
│       └── 第一幕 来信/             大章：卷下面再一层文件夹
│           ├── 第1章 雾里来信.md
│           └── 第2章 灯塔.md
├── 大纲/        （也认：细纲/ outline/ outlines/）
│   ├── 全书.md                      全书大纲（也认：总纲.md、book.md）
│   ├── 第一卷 雾港.md               卷纲：和卷的文件夹同名
│   └── 第一卷 雾港/
│       ├── 第一幕 来信.md           大章的大纲：和大章的文件夹同名
│       └── 第一幕 来信/
│           └── 第2章 灯塔.md        本章大纲：和章节同名
└── 摘要/        和章节同名的文件就是那一章的摘要（也认：summary/ summaries/）
    └── 第1章 雾里来信.md
```

写某一章时，它上面每一层的大纲都会自动带上：全书、卷、大章、本章。规则只有两条：

- **正文目录下的每一层文件夹就是一层**，层数不限：可以不分卷直接放章，可以只分卷，也可以卷下面再分大章、大章下面再分。
- **大纲文件和它对应的东西同名，放在大纲目录里同样的位置**：章的大纲和章节文件同名，一层的大纲和那层的文件夹同名（`正文/第一卷 雾港/` → `大纲/第一卷 雾港.md`）。全书大纲叫 `全书.md`，直接放在大纲目录下；这个名字可以在 `novelHelper.files.bookNames` 里改。

哪一层没有大纲文件就跳过，不影响别的层。大纲和摘要也可以放得比正文浅：`大纲/第31章.md`、`摘要/第31章.md` 对 `正文/卷二/第31章.md` 同样有效；两处都有时，用位置对得上的那个。别的卷里同名的文件不会被拿来用（`大纲/卷一/第1章.md` 不会配给 `正文/卷二/第1章.md`）。

不分卷、所有章节直接放在 `正文/` 下的摆法照常能用。

一条设定就是一个 Markdown（或 `.txt`）文件，文件名就是条目名。frontmatter 可写可不写：

```markdown
---
name: 林小满                 # 不写就用文件名
aliases: [小满, 林姑娘]      # 别名，正文里出现也算提到
type: 人物                   # 随便写，设定卡上会显示
always: true                 # 常驻：每次请求都带，适合文风要求、世界观总则
summary: 十七岁，雾港邮局的送信员……   # 有摘要时发摘要，不发下面的正文
---
条目正文。没有摘要时发正文的前 500 字。
```

章节按路径排序，数字按大小比：第2章 在 第10章 前面，第九章 在 第十二章 前面，卷二 在 卷十 前面。

## 大纲图和浮标

大纲不只是每章一份提纲：整个大纲目录是一张图，章节在图上有一个位置（浮标），续写按这个位置带大纲。

**节点和顺序。** 大纲目录下的文件夹、文件、文件里的每个标题都是节点：文件夹套文件，文件套标题，全书大纲文件是最上面的根。和文件夹同名的文件（`第一卷 雾港.md` 和 `第一卷 雾港/`）是同一个节点，文件里写的是这个文件夹讲什么。文件开头单独的一个 `# 标题` 是文件自己的标题，不算节点；没有标题的文件自己是一个节点。节点的内容是它的标题下面、下一个标题之前的文字。

没有下级的节点（叶子）按顺序排成故事的主线：文件按名字排（数字按大小比，和章节一样），标题按写的顺序。每个叶子默认接到下一个叶子。大纲不必和正文目录一一对应：一个大纲文件可以管好几章，一章也可以跨几个节点。

**连线。** 节点里单独写一行 `→ 节点标题`（也认 `->`），表示可以从这个节点接到那个节点，用来写分叉、汇合和跳线：

```markdown
## 渡海

陆青山不肯摆渡，林小满和陆青说服他。

→ 点灯
→ 第二卷 回潮/第13章#船回来
```

标题重名时写成 `大纲目录内的路径#标题`（扩展名可写可不写），`#标题` 指同一个文件里的标题；重名的两个里有一个在同一个文件里，就认它。找不到或者有歧义的连线会在边栏的「大纲」视图里标出来。连到一个有下级的节点，等于连到它的第一个叶子；写在有下级的节点上的连线，从它的最后一个叶子出发。

**浮标。** 每章有一到两个浮标，都落在叶子上，三种状态：写到某个节点里；正从一个节点衔接到另一个；同时在写两个节点（并叙）。有浮标的章节，续写带的大纲是：全书大纲、浮标节点的各级上级、浮标节点本身、主线上的下一个节点（最多 `novelHelper.context.nextNodeChars` 字），外加一句「正文现在写到【…】」；设定条目也按浮标节点里提到的名字带。没有浮标的章节和以前一样，按路径找同名的大纲文件。

- 刚开头的章节（正文不到 200 字）第一次要续写时自动放好，不问模型：接着上一章最后的位置；上一章没有浮标，就放在同名大纲文件的第一个叶子上。
- 之后本章正文每净增 1000 字（`novelHelper.position.updateChars`，`0` 关掉；字是 Tab 来的还是手打的都算），在你要续写的时候顺带在后台问一次模型：还在原地、开始往相邻的节点过渡、已经到了相邻的节点，还是退回了上一个。它只能沿连线挪一步，两个并叙的浮标各自判断；回答看不懂就当没动。这一次续写不等它，照用旧位置。
- 已经写了一段却还没有浮标的章节（比如中途开始用），或者浮标的节点在大纲里改了名、删掉了：让模型在全部叶子里找一次。也可以随时运行 **Novel Helper: 让 AI 重新定位大纲位置（浮标）**。
- 这些请求用续写的服务商和模型，回答只是一个编号，在「查看用量」里单独列一行。续写关着、没有 key、到了日上限时不发。

**手动调。** 边栏的「大纲」视图把节点列成树，标出当前章节的浮标在哪；点节点打开文件并跳到那个标题。节点上的操作：把浮标放到这里、设为衔接的目标、加为并叙的第二个浮标、取消第二个。视图标题栏和命令面板里有前进一格、后退一格、让 AI 重新定位。手动放的位置算数，之后的自动判断从它接着走。焦点在大纲文件里时，这些操作说的仍然是你上一个打开的章节。状态栏按钮的提示里也写着当前位置。

浮标存在故事目录的 `.novel-helper/buoys/` 下，一章一个 JSON 文件（`.novel-helper/buoys/正文/…/第2章 灯塔.md.json`），不写进正文。每次变动记一条：正文写到哪里时浮标在哪，最后一条就是当前位置。在边栏或资源管理器里给章节、卷改名时，这些文件跟着走；大纲文件改名时，里面记的节点也跟着改。在大纲里改了标题的名字，那个节点上的浮标就对不上了，「大纲」视图会写明，下次续写时让模型重新找。

## 写的时候

- 在章节文件的行尾停一下，750 毫秒后出灰字。**Tab** 收下；**Esc** 或者接着打字就放弃，还在跑的请求也会一起断掉。
- 在任何 Markdown 或纯文本文件里按 **Alt+\\**，马上要一条。
- 状态栏上的按钮显示开、关、请求中，点一下切换开关。`novelHelper.trigger` 设成 `manual` 就只在按 Alt+\\ 时请求。
- 灰字最多 100 字（`novelHelper.maxSuggestionChars`，标点、换行和段首缩进都算），可以有好几句，也可以跨段。模型可以在句末的自然停顿处提前结束，不用写满；写超了就截到上限以内最后一个 。！？…（连同后面的引号），上限以内没有句末标点才在上限处硬截。
- 分段跟着正文已有的写法：段与段之间空一行还是只换行、段首有没有全角空格缩进，都按光标前的正文来，模型写得不一样也会改成一样。光标前的那一行已经写完（以句末标点或冒号结尾，或者是标题行）时，灰字可以从另起一段开始。
- 提示词要求每次续写都把情节往前推：章节在大纲上有位置（[浮标](#大纲图和浮标)）时，顺着当前节点往下写，写完了朝下一个节点过渡，不越过它往后跳；没有浮标、有本章大纲时，对照正文看大纲里哪些已经写到，朝下一个还没写到的点走，不重写写过的，也不一步跳到很后面；没有本章大纲时，每次带来新的动作、对话、信息或局面变化，不把上文说过的换个说法再写一遍。不能和设定冲突，设定里没有的关键设定（世界规则、人物背景和关系）不编；情节怎么走、场景里的小细节由模型写。
- 模型回「好的，以下是续写：……」这类话时不显示。
- 输入法还在组字时（中文后面跟着拼音字母）不会自动发请求。

## 看喂了什么

命令面板 → **Novel Helper: 查看上次发给模型的内容**，打开一个只读页面，内容是上一次完成的请求：

- 带上了哪些条目，为什么带：常驻，还是哪些名字命中、命中几次、离光标多近、大纲里有没有提到；各用了多少字，用的是摘要还是正文；
- 哪些条目因为预算用完没带上；
- 每一层大纲用了哪个文件、多少字、有没有被截断，哪一层没有大纲；章节在大纲上的位置（浮标），带了哪几个节点；用了哪几章前文，各多少字；
- 这次请求的用量：全价输入、缓存读取、缓存写入、输出各多少 token，按单价估出来的花费；
- 完整的提示词（按缓存断点分段）、请求参数（不含 key）、模型原始返回、截成灰字后的结果，以及耗时。

模型没用上你以为它知道的设定时，看这一页就知道是名字没找到，还是预算满了。

## 一次请求里有什么

按下面的顺序排，越不变的越靠前：

1. 指令和常驻条目。
2. 各层大纲，从大到小：全书、卷、大章；然后是前面几章（有摘要用摘要，没有就用那一章的结尾）和本章大纲。上层大纲各有字数上限，超了截断。章节有[浮标](#大纲图和浮标)时，这一块换成：全书大纲、浮标节点的各级上级、前面几章、当前位置（浮标节点和它的下一个节点）；浮标一千字左右才挪一次，挪的时候这一块之后的缓存重来一次。
3. 名字或别名出现在本章光标前的正文里、或者出现在本章大纲（有浮标时是浮标节点）里的条目。每处提到都算分，离光标越近分越高；预算不够时留分高的。上层大纲里的名字不算，不然全书大纲会把所有人物都带进来。
4. 本章正文，从章首到光标，以及光标后的一小段。

名字按最长匹配：「张三丰」不会算成「张三」。含英文字母的名字不分大小写，而且要整词：`Al` 不会命中 `Also`。

## 花多少钱

写一章要发很多次请求，每次的提示词大半和上一次相同。服务商对「和之前的请求开头相同的部分」按大约一成的价格收费（提示词缓存），所以提示词是按「上一次请求是下一次的开头」来排的：

- 正文从章首发起，不是只发光标前的一小段：往下写的时候，前面的内容一个字都不变。章节超过 `novelHelper.context.beforeChars`（默认 6000 字）时，每次从开头去掉三分之一，而不是每写一个字就挪一下。
- 设定条目排在正文前面，按在本章第一次出现的先后排：新提到一个名字，只是在末尾加一条。
- 正文按行切成每段三百来字，缓存断点放在各层大纲后面，以及最后两段写完的正文后面。每次请求从缓存读到上一个断点，再把新写完的一段写进缓存。

结果是：连着写的时候，一次请求里按全价算的只有正在写的那一小段（平均一两百字）和收尾的一句指令，其余都按缓存价。停下超过缓存的有效期再回来，第一次请求要把整个提示词重新写进缓存。

| 服务商 | 缓存怎么用上 | 有效期 | 默认模型的单价（每百万 token，美元；2026-11-12 查的官方定价） |
|---|---|---|---|
| Anthropic | 请求里标断点 | 5 分钟，每次命中续期 | 输入 0.10，缓存写入 0.125，缓存读取 0.01，输出 0.50 |
| OpenAI | 请求里标断点（GPT-5.6 及之后） | 30 分钟 | 输入 0.10，缓存写入 0.125，缓存读取 0.01，输出 0.50 |
| DeepSeek | 服务商自动认相同的开头，尽力而为 | 几小时到几天 | 输入 0.15，缓存命中 0.003，输出 0.60；周一到周五 UTC 01:00–04:00 和 06:00–10:00 加倍 |
| Gemini | 原生接口自动缓存；OpenAI 兼容端点官方没说 | | 输入 0.30，缓存 0.03，输出 2.50；有免费档 |

提示词太短时不进缓存（Anthropic 要 512 token 以上，OpenAI 1024）。

**看用量：**

- 鼠标停在状态栏的按钮上，看今天的请求数、各类 token 数和估算花费。
- 命令面板 → **Novel Helper: 查看用量和估算花费**，看今天和本月的明细，按服务商和模型分开，还有缓存读取占输入的比例。
- 「查看上次发给模型的内容」里有上一次请求的用量。

用量取自服务商对每次请求返回的数字。花费是 token 数乘单价，只是估算，以服务商的账单为准。几点说明：

- 被打字打断的请求会马上断开。这时服务商已经给了用量的照常计入（Anthropic 在流的开头就给输入用量，一般已经有了）；还没给的只算进请求数，用量记为「未知」。
- 模型在字数上限以内自己停下时，流正常结束，用量照常拿到。写超了上限，灰字就不再等后面的内容。Anthropic 在流的开头就给输入用量，所以马上断开，输出 token 按收到的文字估，页面上会标明是估的。OpenAI 兼容的接口在流的最后才给用量，所以这时连接会再留最多 2 秒等它；等不到就记为「未知」，不编数字。本地模型不等。
- 每次请求的输出上限是字数上限的两倍 token（默认 200）：中文一个字大约 0.8 到 1.35 token，英文一个字符大约 0.25。模型撞到这个上限时，灰字截到最后一个句末标点。
- 模型换成了默认以外的，扩展不知道单价，就只统计 token 数。要算花费，在 `novelHelper.usage.prices` 里填：

  ```json
  "novelHelper.usage.prices": {
    "claude-sonnet-5-5": { "input": 2, "output": 10, "cacheRead": 0.1, "cacheWrite": 2.5 }
  }
  ```

- DeepSeek 的高峰时段按时间自动换算；中国法定节假日不算高峰，这一点没有处理。Gemini 按付费档算，用免费档时实际不花钱。
- 累计数存在扩展运行的那台机器上（用 Remote-SSH 时是远程机器），保留本月和上个月，所有窗口共用。

**日上限：** `novelHelper.usage.dailyLimitUsd` 填一个美元数，当天的估算花费到了就停止自动请求，状态栏会提示；按 **Alt+\\** 仍然可以手动要一条。默认 `0`，不限。没有单价的请求不计入。

## 助手

边栏里的第五个视图「助手」是一个对话面板，背后是一个能读、能改整个故事目录的 agent。灰字续写管的是光标后面的一小段；「把选中这段改得紧凑些」「第三卷的大纲和已经写的正文对得上吗」「给这一章补一份摘要」这类事在这里说。面板可以拖到右边的副边栏，和编辑器并排。

**要先装什么**

- Node.js 22 或更高。扩展用 `npx` 启动 agent 的适配器；适配器不在扩展包里，第一次启动时下载（几百 MB，要等几分钟），之后从 npx 的缓存启动，一两秒。
- Claude Code，并且登录过：在终端里运行 `claude`，按提示登录。助手用的就是这台机器上 Claude Code 自己的登录和订阅额度，不走 API 额度。扩展不经手任何密钥，灰字续写用的 API key 也不会给它。（环境变量里设了 `ANTHROPIC_API_KEY` 的话，Claude Code 会按它自己的规则改用这个 key 计费。）
- 用 Remote-SSH 时 agent 跑在远程机器上，Node.js 和登录都要在那台机器上。

**怎么选 agent**

| `novelHelper.assistant.agent` | |
|---|---|
| `claude`（默认） | Claude Code，通过适配器 `@agentclientprotocol/claude-agent-acp`。版本固定在扩展里（现在是 0.106.0），跟着扩展的版本升：适配器发版很勤、还在 0.x，`npx` 拿到什么就运行什么，而它够得着你的全部文件；固定版本也让它每次直接从缓存启动，不用联网问有没有新版。 |
| `custom` | 任何在标准输入输出上讲 [Agent Client Protocol](https://agentclientprotocol.com) 的 agent：`novelHelper.assistant.command` 填启动命令，`novelHelper.assistant.args` 填参数。比如 Gemini CLI 是命令 `gemini`、参数 `["--acp"]`。别家 agent 没有逐个测过，不保证体验。 |

这几项只认用户设置（远程窗口里是远程设置），写在工作区设置里不算：打开一个文件夹，不会由它决定运行什么命令。受限模式下（没信任的文件夹）助手不可用。

**它知道什么**

- 每个会话开头，扩展给它一份工作区说明：目录怎么摆（用的是这本书实际的目录名）、大纲和摘要怎么对应章节、设定的 frontmatter 字段、大纲图怎么读和浮标怎么挪、它可以改什么。
- 每条消息自动附上当前打开的文件、光标在第几行、选中的文字和它的位置；输入框上方写着这次带的是什么。所以可以直接说「这段」「这一章」。
- 发消息之前，故事目录里没保存的文件会先保存：Claude Code 自己读写磁盘，不经过编辑器。

**权限**

- 故事目录里的读、搜、改（包括正文）直接放行，不逐个问。`.novel-helper/` 里快照以外的内容（各章的浮标、设定模板、`project.json`）也是故事的一部分：一样放行，一样进快照、能退回。
- 其他的在面板里问你，不点就是不放行：运行命令、联网、故事目录外面的路径，故事目录里其他以点开头的文件夹（`.git`、`.vscode` 这些放的是工具的配置）和快照目录 `.novel-helper/snapshots/`，还有快照管不到的文件（非文本、超过 5 MB 的，见下）：改了它们就退不回来。符号链接按它指向的真实位置算。
- 问你的时候只有两个选项：允许这一次、不允许。agent 自己还给了别的选项（「以后都允许」这类）的话，面板不显示：答应一次管到以后，后面的请求就绕过上面的规则了。
- 对 Claude Code，扩展会把会话切到它「每次都问」的模式，再由上面的规则决定放不放行。你自己在 Claude Code 的设置里写的 allow 规则仍然先生效；Claude Code 认定只读的命令（`ls`、`cat`、`echo` 这类）它也不会来问。自定义 agent 用它自己的默认模式。

**挪浮标**

- 助手可以挪一章在[大纲图](#大纲图和浮标)上的位置：让它挪，或者它改了大纲的标题、结构之后把对不上的章节跟着挪过去（工作区说明里要求它这么做）。
- 它的做法是在那一章的浮标文件末尾追加一条只写了位置的记录（`{ "by": "assistant", "state": … }`）。正文写到第几个字、当时有多少字这些数，模型自己算不准，所以不让它写：扩展下一次读到这个文件时，按章节当时的正文补上，写回文件。
- 记录里的节点在大纲里找不到时，和别的记录一样算位置丢失，下次续写让模型重新找。
- 一轮结束后、退回之后，「大纲」视图和状态栏提示里的位置跟着更新。浮标文件在快照里，挪错了退回这一轮就行。

**快照和退回**

- 每一轮开始前，扩展把故事目录里的文本文件存一份快照，放在故事目录的 `.novel-helper/snapshots/` 下，按内容寻址，相同的内容只存一份。一轮结束后把目录重新读一遍和快照比对，得出这一轮新建、修改、删除了哪些文件；agent 怎么写的盘都一样能查出来。
- 每一轮的末尾列出改动的文件。点文件名，用 VS Code 的差异编辑器看这一轮前后的差别；文件还是这一轮留下的样子时，右边就是文件本身，可以直接改。
- **退回到这一轮之前**：这一轮开始之后变过的文件都恢复成当时的样子，之后新建的删掉，删掉的还原；这之后你自己手改的也一起退回。退回前会问一次，并且先把现在的样子再存一份快照，所以退回本身也能撤销（**撤销这次退回**）。有未保存修改的文件会先保存，一起进这份快照。
- 新开会话后面板清空，快照还在：命令面板 → **Novel Helper: 助手：退回到某一轮之前…** 列出所有保留的快照。
- 保留最近 50 份（`novelHelper.assistant.snapshots.keep`），更早的清掉，不再被引用的内容一起清。没改动文件的一轮不留快照。
- 不进快照的：`.novel-helper/snapshots/` 本身、任何位置的 `.git` 和 `node_modules` 文件夹、超过 5 MB 的文件、非文本文件（开头 8000 字节里有 NUL 字节）、符号链接。这些文件被改了不会列出来，退回也不动它们。退回不删空文件夹。
- 退回要写回的某个文件，位置上现在如果是快照不收的东西（它变成了超过 5 MB 的文件、非文本文件、符号链接或文件夹，或者它上面某一层文件夹成了符号链接或文件），整次退回就不做：一个文件都不动，弹窗列出是哪些文件、各是什么情况。覆盖这样的文件撤销不回来；只退其余的文件，又会留下一个半新半旧、从来没有存在过的故事目录。把这些文件挪走或改名，再退回一次。
- 快照不依赖 git，也不碰你自己的 git 仓库。`.novel-helper/snapshots/` 里有一个内容是 `*` 的 `.gitignore`，用 git 管小说时快照不会被提交。
- agent 改了一个你正有未保存修改的文件时，编辑器里留着你的版本，面板会提示，保存时 VS Code 会问留哪一个。没有未保存修改的文件，VS Code 自己重新加载。

```text
.novel-helper/snapshots/
├── .gitignore
├── objects/
│   ├── 2d/2cc7a1…          一份文件内容，名字是内容的 SHA-256
│   └── 47/2d6086…
└── turns/
    ├── 000012.json          一轮：开始前每个文件的哈希，结束后记下这一轮的改动
    └── 000013.json          一次退回，格式相同
```

**会话**

- 窗口开着时会话一直在。重开窗口后面板显示之前的对话；agent 能接上旧会话的话（Claude Code 能）就接着聊，否则会说明这是新会话。
- agent 进程中途退出时，面板会说明，下一条消息会重新启动它并接上会话。
- 视图标题栏的 **+** 新开会话；有一轮正在进行时，先取消这一轮，再清空面板。**停止** 取消当前这一轮，还没回答的许可请求按不放行算。
- 启动不了时，面板会说是哪一种情况、该怎么办：找不到 `npx`、agent 没登录、刚启动就退出（附它最后的输出）。agent 写到 stderr 的内容在输出面板的「Novel Helper」里。

## 看设定

- 在任何 Markdown 或纯文本文件里，鼠标停在名字或别名上就出设定卡；不用鼠标的话，光标放在名字上按 **Ctrl+K Ctrl+I**。
- **F12** 打开设定文件；**Alt+F12**（Linux 上是 **Ctrl+Shift+F10**）在原地展开，可以直接改。
- 设定文件保存、新建、改名、删除后马上生效。

| `novelHelper.files.bookNames` | `全书`、`总纲`、`book` | 全书大纲的文件名（不含扩展名） |
| `novelHelper.context.beforeChars` | `6000` | 本章光标前的正文最多发多少；名字也在这段里找 |
| `novelHelper.context.afterChars` | `200` | 发给模型的光标后正文 |
| `novelHelper.context.alwaysChars` | `1500` | 常驻条目的预算 |
| `novelHelper.context.matchedChars` | `2500` | 命中条目的预算 |
| `novelHelper.context.entryChars` | `500` | 每条最多取多少 |
| `novelHelper.context.bookOutlineChars` | `1000` | 全书大纲最多取多少 |
| `novelHelper.context.levelOutlineChars` | `800` | 卷、大章这些中间层，每层的大纲最多取多少 |
| `novelHelper.context.outlineChars` | `800` | 本章大纲最多取多少；有浮标时是每个浮标节点最多取多少 |
| `novelHelper.context.nextNodeChars` | `300` | 有浮标时，下一个节点最多取多少 |
| `novelHelper.position.updateChars` | `1000` | 本章正文净增多少字就让模型再判断一次浮标；`0` 关掉自动更新 |
| `novelHelper.context.previousChapters` | `3` | 带前面几章 |
| `novelHelper.context.previousChapterChars` | `400` | 每个前面章节最多取多少 |

长度都按字算，一个汉字算一个。`files` 和 `context` 两组设置可以按工作区文件夹分别设。0.1.0 的 `novelHelper.context.scanChars` 已经去掉：名字现在在发出去的整段正文里找。

## 试一下示例

1. 把本仓库的 [`examples/`](examples) 文件夹当工作区打开，设好 key。点活动栏上的「小说助手」图标，看书的结构和设定两棵树。
2. 打开 `正文/第一卷 雾港/第一幕 来信/第2章 灯塔.md`，光标放到最后一行末尾，等灰字出来。「大纲」视图里，这一章的浮标在「周伯收信」上（示例带着它的浮标文件 `.novel-helper/buoys/…`）。
3. 运行「查看上次发给模型的内容」看带了什么：全书大纲，「第一卷 雾港」「第一幕 来信」这两级上级，当前位置「周伯收信」和下一个节点「商量渡海」；「陆青山」按自己命中，没有算成「陆青」。把浮标挪回「等门」再要一条，潮汐钟就会因为那个节点提到它而带上（正文里只写了钟声）。
4. 再要一条灰字，然后运行「查看用量和估算花费」，看第二次请求有多少输入是从缓存读的。

第1章 有摘要，第2章 没有：在同一个文件夹里新建 `第3章.md` 写几个字，它的请求里带的就是第2章 的结尾，浮标接着第2章 的放在「周伯收信」上。
