# Novel Helper for Mac

[English](README.md)

为中文长篇小说做的 macOS 写作应用，使用 Electron、React 和 CodeMirror 6。一本书就是一个 Markdown 和文本文件夹。灰字续写参考设定、人物、大纲和前文，两侧可以看设定、大纲，也可以和能改全书的 ACP 助手讨论。

界面为中文。VS Code 扩展保留在 [`vscode-extension`](https://github.com/Hebi8/novel-helper/tree/vscode-extension) 分支。书的磁盘格式不变，两边都能打开。

## 从源码运行和打包

在 Apple Silicon Mac 上安装 Node.js 22 或更新版本，然后运行：

```sh
npm ci
npm run dev
```

```sh
npm run check
npm test
npm run build
npm run e2e
npm run pack
```

`pack` 在 `release/mac-arm64/Novel Helper.app` 输出不签名的 arm64 应用，使用默认 Electron 图标。只构建目录，不出 DMG，不做公证和自动更新。

## 打开或新建一本书

按 **⌘O** 或欢迎页的 **打开文件夹**。所选目录已经有标记就直接打开。没有标记时，先查看下面最多四层内带标记的书：有就列出来供选择，当前目录也有书的文件时把它放在第一项，选中后才补标记；没有下层书但当前目录有书的文件时，直接补标记打开；都没有则进入初始化：选中文或英文目录名，再勾选要建的目录和起始文件。已经有的不列出，也不会覆盖。

欢迎页的 **新建一本书** 走同一流程，可以在系统对话框里新建文件夹。一本书一个窗口，再开同一本书会切到已有窗口。下次启动恢复上次的书、标签页和光标。

## 操作一览

| 做什么 | 快捷键或入口 |
|---|---|
| 收下、放弃灰字 | Tab、Esc；接着打字也放弃 |
| 只收下一句 | ⌘→ |
| 手动续写 | ⌥\ |
| 新建章，编号自动接上 | ⌘N、顶栏、章节树右键 |
| 新建卷或下一层，连第一章一起建 | 章节树右键 |
| 重命名章或层级，带走大纲、摘要、浮标 | 章节树右键 |
| 在访达中显示 | 章节、大纲、设定条目右键 |
| 快速打开 | ⌘P |
| 本文件查找和替换 | ⌘F |
| 全书搜索 | ⌘⇧F；字面匹配、不分大小写，显示总数和前 200 处，不做全书替换 |
| 设定卡、打开设定、并排打开设定 | ⌘I、F12、⌥F12 |
| 并排、专注 | ⌘\、⌃⌘F |
| 左栏三个分区、收起左栏 | ⌘1–3、⌘0 |
| 右栏三个页签、收起右栏 | ⌥⌘1–3、⌥⌘0 |
| 光标进助手、停止助手 | ⌘L、⌘. |
| 设置 | ⌘, |

左栏是章节、大纲和设定的编辑入口；右栏快速查看大纲、设定，以及使用助手。中间的标签页按原样编辑 Markdown。字体、字号和当前行自动居中可设置，颜色跟随系统。专注模式全屏隐藏两侧和顶栏、标签栏、底栏，再按一次恢复原来的边栏状态；Esc 留给灰字。

停止打字一秒后自动保存；切标签页、窗口失去焦点、给助手发消息之前也保存。搜索和重命名前先保存未保存内容。输入法组字期间不提交弹层、不发送、不抢回车和 Esc。磁盘外部改动会自动重读；有未保存内容时停下来显示冲突，可以看差异、留我的或用磁盘的。保留原换行符，非 UTF-8 或混合换行符的文件不打开来改。没有删除文件、拖动文件或拖动排序的操作。

完整行为见 [`docs/ux.md`](docs/ux.md)，窗口布局见 [`docs/layout.html`](docs/layout.html)。

## 书的文件夹

```text
我的小说/
├── 正文/
│   └── 第一卷 雾港/
│       ├── 第1章 雾里来信.md
│       └── 第2章 灯塔.md
├── 大纲/
│   ├── 全书.md
│   ├── 第一卷 雾港.md
│   └── 第一卷 雾港/
│       └── 第2章 灯塔.md
├── 摘要/
│   └── 第1章 雾里来信.md
├── 人物/
│   └── 林小满.md
└── 设定/
    └── 文风.md
```

默认认识这些中文、英文目录：

- 正文：`正文`、`章节`、`chapters`、`manuscript`。
- 大纲：`大纲`、`细纲`、`outline`、`outlines`。
- 摘要：`摘要`、`summary`、`summaries`。
- 设定：`设定`、`人物`、`角色`、`资料`、`世界观`、`lore`、`characters`、`worldbuilding`。

每章一个 `.md` 或 `.txt` 文件。正文目录下每层文件夹就是一层，可不分卷，也可逐层分卷、幕、大章。大纲和对应章或层级同名：`正文/第一卷 雾港/第2章 灯塔.md` 对应 `大纲/第一卷 雾港/第2章 灯塔.md`，卷纲是 `大纲/第一卷 雾港.md`。全书大纲默认叫 `全书.md`、`总纲.md` 或 `book.md`。

大纲和摘要可以放得比正文浅；优先使用层级匹配的文件，不会误拿别卷的同名文件。没有某一层大纲就跳过。章节按路径自然排序，阿拉伯数字和中文数字都按大小比较。

一条设定就是一个文件，文件名是默认名字。可以写 YAML frontmatter：

```markdown
---
name: 林小满
aliases: [小满, 林姑娘]
type: 人物
always: true
summary: 十七岁，雾港邮局的送信员。
---
这里写条目正文。
```

`name` 不写就用文件名；`aliases` 里的别名也算提到；`type` 是作者自己起的类型，没写就用顶层文件夹名；`always` 表示每次请求都带；有 `summary` 时发摘要，没有则按单条预算取正文。名字优先最长匹配，英文名按整词匹配且不分大小写。左栏右键切常驻、改别名、改类型，只改那个 frontmatter 字段；不能无损改写时停下来说明。

设定模板放在 `.novel-helper/templates/`，按类型命名，通用模板叫 `default.md`。可用 `{{name}}`、`{{type}}`。

## 大纲和浮标

大纲目录里的文件夹、文件和标题组成一张图。同名的文件与文件夹代表同一个节点。文件开头单独的 `# 标题` 是文件的标题；其余标题按写下的顺序成为节点。没有下级的叶子节点顺序串成主线，文件按自然顺序排列。

单独一行 `→ 节点标题`（也认 `->`）表示连线。重名时用 `路径#标题`，扩展名可省；同文件里可用 `#标题`：

```markdown
## 渡海

林小满和陆青说服船夫摆渡。

→ 点灯
→ Volume 2/Chapter 13#船回来
```

每章一到两个浮标：写到某个节点、从一个节点衔接到另一个、同时在写两个节点。右栏可以放到这里、设为衔接目标、加为并叙、取消第二个，以及前进、后退和重新定位。编辑大纲文件时，操作对象仍是上一个打开的章节。

浮标存在 `.novel-helper/buoys/<章节路径>.json`，每次变动留一条记录，不写进正文。短的新章从上一章的位置或同名大纲起点开始。默认每净增 1000 字，在下次续写时顺带判断是否沿连线移动一步；`position.updateChars` 设为 `0` 可关闭自动更新。没有位置或原节点已丢失时可以重新定位。

从章节树重命名时，正文、大纲、摘要、浮标文件路径和记录里的节点引用一起更新。文件改名使用硬链接保证不覆盖已有文件；exFAT 和部分网络盘不支持，在这些盘上章节改不了名，应用会说明原因，不改动文件。

共用的大纲或摘要、目标已占用、只改大小写、无法解析的浮标记录，会在动手前阻止改名。中途意外失败时，停止并列出已完成和未完成的操作，标签页跟随实际的新路径，不回滚。

续写依次参考常驻设定、全书和各层大纲、前文（有摘要用摘要）、浮标当前节点和下一节点、匹配设定、光标前后正文。没有浮标时按同名文件找本章大纲。**续写** 菜单里可打开上次请求内容和用量的只读报告。

## 设置

**⌘,** 打开分组的设置行：续写、模型与请求、上下文、目录规则、用量、写作面板、快照、助手。数字和文字行内编辑；数组和对象在小弹层里编辑 JSON，解析失败不保存。默认值见 [`src/shared/defaults.ts`](src/shared/defaults.ts)。应用没有 `files.storyFolder` 这一层，所选文件夹就是书的根。

支持 Anthropic、OpenAI、DeepSeek、Gemini 和 OpenAI 兼容接口。每个服务商单独设置 API key，只显示是否已设置。兼容接口地址和模型为 `openaiCompatible.baseUrl`、`openaiCompatible.model`，额外请求字段为 `extraRequestBody`。

`usage.prices` 按模型 ID 设置每百万 token 的美元单价，字段为 `input`、`output`、`cacheRead`、`cacheWrite`。`usage.dailyLimitUsd` 是每日估算上限，`0` 为不限；到上限暂停自动请求，手动续写仍可用。不知道单价的请求标为未计价，不当作免费。助手使用自己的账号，不计入续写账本。

这些设置全部存在应用里。书里的配置不能更改服务商、地址、凭证、单价、上限或助手命令。

## 助手需要什么

本机装好 Claude Code 并登录，Node.js 22+ 和 `npx` 可用。应用通过官方 `@agentclientprotocol/claude-agent-acp` 适配器启动它，自己不碰它的登录，也不把续写 API key 交给它。从程序坞启动时会读取登录 shell 的 PATH。

消息带上当前文件、光标和选区。agent 通过 ACP 报出模型或思考档位选项时，发送按钮旁的下拉可以直接切换，并按 agent 记住用户在下拉里选的值（新开或恢复会话时先恢复模型，再按新列表恢复思考档位；记住的值不在本次列表里时显示 agent 当前值，记忆原样保留）。超出可直接放行的书内操作时，面板只给 **允许这一次** 和 **不允许**。预设适配器会使用书目录里的 `.claude` 配置，其中的放行规则和钩子不经过应用许可卡片；使用他人的书前先检查这个目录。

助手每轮前后留快照，列出改动文件，可以看差异、整轮退回；退回写回文稿时先写同目录临时文件再改名覆盖，并先保存现状，因此退回也能撤销。助手快照默认保留 50 份。自定义 ACP agent 用 `assistant.agent`、`assistant.command` 和 JSON 数组 `assistant.args` 配置，改动对下一次启动助手生效。

手打内容也存定时快照：距上一份快照（不论定时还是助手快照）达到设定间隔（`snapshots.intervalMinutes`，默认 `10` 分钟；填 `0` 关闭，不读基线也不驻留全书内容，从 `0` 改为非 `0` 时对已打开的书以那一刻的内容建立基线）后，保存、新建、改名或改写完成会在后台存一份整本书的快照，当次操作不等快照结束，失败时不影响已完成的操作并在顶栏提示一次；首次开书基线未读完时的书内写入会先等基线建完再写（基线失败不缓存，建成前只提示一次，下一次写入前重试），后台定时扫描进行时同一本书的下一次写入与助手开轮快照也会等扫描结束再执行。关书、关窗、退出时若上一份快照后有改动也存一份，退出前等待后台快照落盘（助手一轮运行期间不存定时快照）。定时快照默认保留 `100` 份（`snapshots.keep`），与助手快照分开计数，未变文件按内容哈希去重。顶栏 **快照** 将两种快照按时间合并列出，可查看差异并退回到对应时间点，退回本身同样可撤销，且与扩展 0.4.0 的快照存储保持兼容。

## 数据存在哪

- 正文、设定、大纲、摘要留在所选书目录。
- `.novel-helper/project.json` 是标记；浮标、模板、快照也在书内的 `.novel-helper/`。
- 设置、窗口状态、所有窗口共用的用量、按书分开的助手对话，在 `~/Library/Application Support/` 下 Electron 的应用数据目录（默认 `Novel Helper`）。
- API key 沿用 macOS safe storage，由系统钥匙串保管的钥匙加密，存进应用数据目录。
- 日志放在应用数据目录的 `logs/`，**帮助 → 打开日志** 在访达里显示这个目录。
