# Novel Helper for Mac：操作逻辑

这份文档说的是独立 Mac 应用怎么操作、每个操作应该是什么行为。实现以它为准。窗口的样子见 [layout.html](layout.html)（用浏览器打开，两侧的页签可以点）。

应用的操作逻辑和原来的 VS Code 扩展（分支 `vscode-extension`，0.4.0）是同一套：认设定的灰字续写、想看时才调出来的设定卡、大纲图和浮标、能改全书并且每轮可以退回的助手。变的是外壳：一个为写小说做的窗口，不再借用代码编辑器。

一本书是一个 Markdown 文件夹。目录怎么摆、设定的 frontmatter、大纲图和连线、浮标、快照、提示词怎么拼、缓存断点、用量怎么算，都和扩展的 README 写的一样，磁盘上的格式（`.novel-helper/` 下的标记、浮标、快照、模板）完全兼容，同一本书扩展和应用都能开。

## 1. 原样保留的操作

| 操作 | 行为 |
|---|---|
| 灰字出现 | 章节文件行尾停 750 毫秒；最多 100 字，可以分段 |
| 收下、放弃 | Tab 收下；Esc 或接着打字放弃，还在跑的请求一起断开 |
| 手动要一条 | ⌥\\，任何 md 或 txt 里都行 |
| 续写带什么 | 常驻条目、各层大纲或浮标节点、前几章、正文里提到的设定、本章正文；缓存断点不变 |
| 看设定卡 | 悬停在名字上，或光标在名字上按 ⌘I |
| 打开设定文件 | F12 或 ⌘ 点名字 |
| 书的结构 | 全书、卷、大章、章的树；点章打开；标出有没有大纲和摘要 |
| 新建、重命名 | 新建章自动接编号；新建卷连第一章一起建；重命名带走大纲和摘要 |
| 设定 | 按类型分组；切常驻、改别名、改类型只动 frontmatter 里那一个字段 |
| 大纲和浮标 | 树上标着浮标；放到这里、设为衔接目标、加为并叙、取消第二个、前进、后退、让 AI 重新定位 |
| 浮标自动更新 | 本章每净增 1000 字顺带问一次模型，只沿连线走一步 |
| 设置和用量 | 一行一项，点一下就改；今天和本月的请求数与花费；日上限 |
| 看喂了什么 | 只读页面：带了哪些条目、为什么带、完整提示词、用量 |
| 助手 | 通过 ACP 起本机的 Claude Code；故事目录内的改动放行，其余在面板里问；只有「允许一次」和「拒绝」 |
| 快照和退回 | 每轮前后存快照；看差异；整轮退回，退回本身可以撤销 |
| 不做的 | 不在界面里删除文件、拖动排序；不用表单填内容，内容一律在 md 里写 |
| 文稿安全 | 拿不准能不能无损改写或改名就停下报错，不动文件 |

## 2. 窗口

### 2.1 分区

- **中间是写作面板**。正文限宽居中，窗口宽了两侧自动留白。没有行号、小地图、面包屑。上面一排标签页。
- **左栏是编辑入口**。三个分区：章节、大纲、设定。点一下，对应的 md 在中间的标签页里打开，用完整的编辑器改。新建章、新建卷、新建设定条目、重命名、切常驻、改别名、改类型都在左栏。
- **右栏只用来快速查看和对照**。三个页签：看大纲、看设定、助手。看大纲和看设定是只读的，每个条目旁边有「在中间打开」。同一个文件不会同时有两处在改。
- **顶栏**一排图标：收起左栏、并排、书名、新建章；右边是查找、快照、设置、收起右栏。
- **底栏**：续写开关和请求状态，点一下切换；今天的请求数和花费，点开是明细；当前章节的浮标；最右是本章字数。
- 两侧都能收起。专注模式全屏并收起两侧，只剩正文。
- 设置和用量在设置窗口里，不占边栏。
- 界面上不放「点一下打开」这类操作提示文字。

### 2.2 左栏

- **章节**：书的结构树。每个节点后面标着有没有大纲、摘要。正在编辑的章在树里选中。
- **大纲**：大纲目录里的文件，按层级列出，点一下打开来改。
- **设定**：按类型分组。分组用条目 frontmatter 里的 `type`，没写就用它所在的顶层文件夹名。世界观、人物、物品、势力这些分类由作者自己起名；新建条目时选已有的类型或输入一个新的。右键切常驻、改别名、改类型。

### 2.3 右栏

- **看大纲**：大纲图列成树，标着当前章节的浮标。下面显示选中节点的内容和主线上的下一个节点。浮标的全部操作在这里。焦点在别的文件里时，这些操作说的仍然是上一个打开的章节。
- **看设定**：顶上一个按名字或别名找的输入框，下面是分组列表和选中条目的卡片：名字、类型、是否常驻、别名、摘要和正文。
- **助手**：对话、许可卡片、每轮改动的文件列表。发消息时自动带上中间正在编辑的文件、光标在第几行、选中的文字。
- 右栏显示什么由作者自己点，不跟着光标自动换内容。唯一自动的是大纲上的浮标标记。

### 2.4 写作面板的手感

参考了纯纯写作（Pure Writer）桌面版的界面，没有使用它的代码。

- Markdown 按原样显示，不渲染、不隐藏标记。标题行稍微加重。设定里的名字下面有一条细点线。
- 段间距只是显示效果，不往正文里插空行。正文本来用空行分段的，不再额外加间距；用的是续写里判断「空行还是换行」的同一段逻辑。
- 回车另起一段时沿用上一段的段首缩进。
- 引号、括号自动补成一对；删左半边时右半边一起删；光标在右引号或右括号前按回车或 Tab 跳出去。有灰字时 Tab 先收灰字。
- 没有灰字、也不在右引号前时，Tab 照常输入一个制表符。
- 可选开关：正在写的那一行自动滚到屏幕中间。
- 默认苹方，字体、字号可换。跟随系统的浅色和深色。
- 并排是左右两个编辑器对照，只做一层。

## 3. 打开一本书

- **一本书就是一个文件夹**。⌘O 选文件夹，选中的文件夹就是故事的根。扩展里「工作区」加「故事目录相对路径」那一层没有了。
- **选的文件夹不是书**：里面最多往下四层有带标记的故事空间时，列出来点一个就打开。空文件夹或没初始化的，走初始化：问目录用中文名还是英文名，列出要建的东西勾选。已经有的不列出来，也不覆盖。
- **启动**：重新打开上次的书、上次的标签页和光标位置。没有上次的书时，显示最近的书、「打开文件夹」和「新建一本书」。
- **多本书**：一本书一个窗口。同一本书再开一次，切到已有的窗口。
- **没有「信任文件夹」**：服务商、模型、地址、key、单价、日上限、助手用的命令只存在应用自己的设置里，从不从书的文件夹读。打开别人给的文件夹改不了这些。
- 预设的 Claude Code 适配器会采用书目录里的 `.claude` 设置，其中的放行规则和钩子不经过应用的许可卡片；用别人给的书之前先看一眼这个目录。
- **目录规则**：认默认的中文和英文目录名。

## 4. 设定卡

- **调出**：鼠标停在名字上约 0.4 秒；或者光标在名字上按 ⌘I。应用不主动弹。
- **内容**：名字、类型、是否常驻、别名、摘要或正文前 300 字。一个名字对应多条设定时，几张卡都列出。
- **卡上的操作**：⌘↩ 或点「打开」在标签页里打开设定文件；⌥⌘↩ 并排打开；Esc 关掉，光标回原处。
- 设定文件保存、新建、改名、删除后马上生效。

## 6. 输入法组字时的灰字

应用拿得到真实的组字状态，不再像扩展那样靠「中文后面跟着小写字母」来猜。

1. **组字开始等于打字**：灰字立刻消失，在跑的请求断开。
2. **组字期间什么都不做**：不计时、不发请求、不显示灰字。Tab、Esc、回车、空格、数字键全归输入法，应用不拦。⌥\\ 这时也不响应。
3. **上屏之后**：按普通打字算，从上屏那一刻起等 750 毫秒，在行尾就发请求。
4. **取消组字**：正文没变。回到同一个位置、正文也相同时，直接显示上一次的灰字，不重新发请求。
5. **没有拼音猜测**：「他说hello」这种中文后面跟英文的行尾，照常自动续写。
6. **助手输入框**：组字期间按回车是选词，不发送。
7. 日文输入法、听写、长按出重音符号、表情面板都走同一套组字状态。

灰字的状态是一个纯函数的状态机：输入是事件（打字、光标移动、组字开始、组字结束、停顿到时、收到回答、Tab、⌘→、Esc、失去焦点），输出是新状态和要做的事（发请求、断开请求、显示、隐藏、插入文字）。上面每一条都有单元测试。

其他规则和扩展一样：自动请求只在章节文件的行尾（光标后面只能有收尾的标点和空白）；⌥\\ 在任何 md 和 txt 里都行；到了日上限不自动发；续写关着不发；收下一次灰字是一步撤销。

## 7. 保存和外部改动

- **自动保存**：停止打字 1 秒后保存；切走标签页、窗口失去焦点、给助手发消息之前也保存。没有手动保存这一步。
- **组字期间不自动保存**：拼音还没上屏时不计时、不存。关窗或退出时先让编辑器失去焦点，输入法随之结束组字，屏幕上的内容照样存下来。
- **换行符和编码**：文件原来用什么换行符，写回去还是什么。不是 UTF-8、或者混用两种换行符的文件不打开来改，在界面上说明原因。
- **什么会触发续写**：只有作者在编辑器里的动作：打字、收下灰字、用鼠标或方向键把光标移到行尾。切标签页、启动时恢复光标、外部改动后重读都不触发。有选区时不出灰字。
- **写盘**：先写临时文件再改名。
- **磁盘上的文件被别处改了**（助手、别的编辑器、git）：编辑器里没有未保存内容时，直接重新读入，光标尽量留在原处。有未保存内容时停下不写，在编辑器顶上提示，三个按钮：看差异、留我的、用磁盘的。
- **撤销**：助手改的内容不进编辑器的撤销，用快照退回。

## 8. 应用自己管的东西

| | 做法 |
|---|---|
| 设置 | 存在 `~/Library/Application Support/` 下应用自己的目录里，项目和扩展的设置一一对应 |
| API key | 用系统钥匙串保管的钥匙加密后存在应用目录里；界面上只显示已设置或未设置，从不显示 key 本身 |
| 用量账本 | 应用自己一份，所有窗口共用 |
| 助手的对话 | 存在应用目录里，按书分开，不进书的文件夹 |
| 找到 `npx` | 从程序坞启动时 PATH 很短；应用启动时跑一次登录 shell 取 PATH |
| 文件监听 | 监听故事文件夹，树和索引跟着更新 |
| 删文件、挪文件 | 不做。树上右键「在访达中显示」 |
| 日志 | 写到应用目录下，菜单里有「打开日志」 |
| 界面语言 | 中文。字符串集中放在一处 |

不支持的：远程文件夹（只能开本机上的文件夹）、多根工作区。

## 9. 代码怎么分

```text
src/core  src/llm  src/storage  src/acp     续写、大纲图、浮标、快照、模型客户端、ACP 客户端；不依赖界面
src/main            主进程：窗口、菜单、打开一本书、索引和文件监听、设置、密钥、用量、浮标、助手
src/preload         主进程给界面开的接口
src/renderer        界面：编辑器、左栏、右栏、标签页、底栏、设置窗口
src/test            单元测试
e2e                 把应用启动起来走一遍的测试
examples            示例书；测试只用它的临时副本
```

- Electron，界面用 React 和 CodeMirror 6。界面进程碰不到 Node，只能走 `src/preload` 开的接口。
- 写文件一律先写临时文件再改名。
- 启动应用的测试用不需要 key 的本地假服务，不碰钥匙串。

- 主进程各功能分别注册 IPC，注册列表在 `src/main/register.ts`；窗口关闭清理通过 `MainContext.onBookClosed` 登记；书索引的 `onChanged`、`onFileChanged` 支持多监听，并返回取消监听函数。
- 左右栏各面板独立，切换或收起只隐藏；面板通过 `useWorkspace().current()` 读取当前文档和选区，通过 `open()`、`saveAll()` 打开和保存。
- 文档管理、欢迎页、顶栏、冲突条分别独立；界面命令在 `shell/commands.ts` 的表中登记。

## 10. 分批

1. **骨架，能写一章**：窗口、菜单栏、顶栏、底栏；打开一本书；左栏的章节分区；编辑器和自动保存；灰字续写和输入法规则；五项设置（续写开关、自动还是手动、服务商、模型、API key）；用量和字数。这一批没有浮标，续写按同名大纲文件带大纲。
2. **看设定、大纲、浮标**：设定卡；左栏的大纲和设定分区；右栏的看大纲和看设定；浮标的整套流程；⌘P；并排；「看喂了什么」和用量明细。
3. **助手**：右栏的助手页签；ACP；许可；快照、差异、退回；对话保存。
4. **搭架子和收尾**：初始化、新建章和卷、重命名、补标记；全部设置项；全书搜索；专注；打包；README。
